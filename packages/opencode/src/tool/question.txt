Use this tool when you need to ask the user questions during execution. This allows you to:
1. Gather user preferences or requirements
2. Clarify ambiguous instructions
3. Get decisions on implementation choices as you work
4. Offer choices to the user about what direction to take

Usage notes:
- When `custom` is enabled (default), a "Type your own answer" option is added automatically; don't include "Other" or catch-all options yourself.
- Answers are returned as arrays of labels; set `multiple: true` to allow selecting more than one.
- If you recommend a specific option, make that the first option in the list and add "(Recommended)" at the end of its label.

Plan-mode note: In plan mode, use this tool to clarify requirements or choose between approaches BEFORE finalizing your plan. Do NOT use this tool to ask "Is my plan ready?" or "Should I proceed?" — use the `plan_exit` tool for plan approval. IMPORTANT: Do not reference "the plan" in your questions (e.g., "Do you have feedback about the plan?", "Does the plan look good?") because the user cannot see the plan in the UI until you call `plan_exit`. If you need plan approval, call `plan_exit` instead.

Preview feature:
When presenting concrete artifacts that users need to visually compare, you may use the optional `preview` field on an option (UI-dependent). Good previews include:
- Code snippets showing different implementations
- ASCII or Markdown mockups of UI layouts
- Diagram variations
- Configuration examples

Do not use previews for simple preference questions where labels and descriptions suffice. Previews are only supported for single-select questions (not when `multiple: true`).
